# PWA Offline Support — Implementation Plan

## Goal

Turn EnviToo into a **Progressive Web App** so attendees can add it to their home screen (native-feel, no App Store) and access their **tickets offline** at the venue when cell reception is poor. Static assets (JS/CSS/fonts) precached for instant repeat visits.

No native code, no App Store submission.

---

## Architecture

```
vite-plugin-pwa  →  generate service worker (Workbox)  →  precache static assets
                    configure runtime caching rules     →  cache pages on visit
                    inject manifest                     →  install prompt
```

---

## Implementation order

### 1. Install dep + configure Vite plugin

**File:** `frontend/package.json`, `frontend/vite.config.ts`

- `npm install vite-plugin-pwa`
- Add `VitePWA` plugin with:
  - `registerType: 'autoUpdate'` — SW updates in background, no prompt
  - `includeAssets: ['favicon.svg']`
  - `manifest`: name `EnviToo`, short_name `EnviToo`, theme_color `#07070d`, bg `#07070d`, display `standalone`, orientation `portrait`, scope `/`, start_url `/`
  - `workbox.globPatterns`: precache all JS/CSS/fonts in dist
  - `runtimeCaching`: rules for API GETs and page navigation

### 2. App icons

**Files:** `frontend/public/icons/`

- Generate `icon-192x192.png` + `icon-512x512.png` from existing `favicon.svg` using `sharp`
- Reference in manifest

### 3. Update index.html

**File:** `frontend/index.html`

- Add `<link rel="manifest" href="/manifest.webmanifest">`
- Add `<meta name="apple-mobile-web-app-capable" content="yes">`
- Add `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`
- Update `<meta name="theme-color">` — already set

### 4. Service worker registration

**File:** `frontend/src/main.tsx` (or a separate `registerSW.ts`)

- `vite-plugin-pwa` auto-injects registration — verify via build output
- By default it generates `registerSW.js` loaded in `main.tsx`

### 5. Caching strategy (runtime rules)

| Route | Strategy | TTL | Why |
|---|---|---|---|
| `/t/:token` (guest ticket) | NetworkFirst | 7 days | **Critical** — venue access offline |
| `/e/:slug` (event detail) | NetworkFirst | 24h | Info available without signal |
| `/home` (my tickets) | NetworkFirst | 24h | Offline access to registrations |
| `/discover` (browse) | NetworkFirst | 1h | Stale > blank |
| All API GETs | NetworkFirst | 5 min | Fresh data when online, fallback when offline |
| `/create`, `/edit`, `/manage` | NetworkOnly | — | No value offline |
| Static assets | CacheFirst (precached) | — | Instant repeat loads |

### 6. Verify

- `npm run build` — confirms manifest + SW generated in `dist/`
- Chrome DevTools → Application → Manifest + Service Workers tabs
- Test offline: DevTools → Network → Offline checkbox, reload

---

## Success criteria

- `dist/manifest.webmanifest` and `dist/sw.js` generated on build
- Install prompt fires on mobile Chrome (meets PWA installability criteria)
- `/t/{token}` page loads from cache when offline (after visiting once online)
- App opens in standalone mode (no browser chrome) when installed
- Build passes, no regressions
